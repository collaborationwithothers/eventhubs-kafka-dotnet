# C12: group.id is limited to 256 characters on Event Hubs Premium

A consumer with a 256-character group.id was assigned partitions in all five repeats, and a 257-character group.id was rejected by the broker in all five, so the proposed C12 verdict is confirmed. The rejection was broker error 24, which librdkafka names as invalid group.id. The workload is synthetic, and the result covers only the subscribe action on document-events.

Proposed verdict: `confirmed`.

## Approved inputs and run

The [approved scenario](https://github.com/collaborationwithothers/eventhubs-kafka-dotnet/blob/7b6834c5e8668e89376597bc2b524c0725326daf/scenarios/C12/scenario.yaml) and [expected outcome](https://github.com/collaborationwithothers/eventhubs-kafka-dotnet/blob/7b6834c5e8668e89376597bc2b524c0725326daf/scenarios/C12/expected.yaml) are unchanged. This report uses only [run 40415641139](https://github.com/collaborationwithothers/eventhubs-kafka-dotnet/actions/runs/40415641139), attempt 1, on `main` at source `7b6834c5e8668e89376597bc2b524c0725326daf`, under [Hari's decision](https://github.com/collaborationwithothers/eventhubs-kafka-dotnet/issues/210#issuecomment-6436044243). The run as a whole concluded `failure` because three configurations of other items, C08 C1, F04 C2 and F04 C3, were not accepted. Both C12 candidates were accepted, each with a successful judge receipt.

Each repeat is one fresh consumer, built from the `EnrichmentConsumer` baseline role and run under the `probe` service account, that subscribes to `document-events`. C1 sets `group.id` to `c12-` followed by 252 `g` characters, and C2 to `c12-` followed by 253; a script measured the two values in the scenario file at 256 and 257 characters. A subscribe succeeds when the partitions-assigned handler fires. The action window is 120000 ms.

The [candidate-derived result](2026-10-27.json) holds both candidates and judge receipts unchanged, from [candidate artifact 12715895816](https://github.com/collaborationwithothers/eventhubs-kafka-dotnet/actions/runs/40415641139/artifacts/12715895816). ## Assessment against expected.yaml

**H1 holds.** C1, 256 characters, was assigned partitions in all five repeats. The troubleshooting guide says "The max length of the `group.id` property is 256 characters" ([troubleshooting guide](https://learn.microsoft.com/en-us/azure/event-hubs/apache-kafka-troubleshooting-guide), read 2026-10-27).

**H2 holds.** C2, 257 characters, errored in all five repeats with origin `broker`. The quotas page lists the Kafka consumer group name size as "Kafka: 256 characters" ([quotas page](https://learn.microsoft.com/en-us/azure/event-hubs/event-hubs-quotas), read 2026-10-27). No Microsoft source names the error code; code 24 is reported, not judged.

**Verdict.** `confirmed_when: "C1 succeeds and C2 errors with origin broker."` holds, so the proposed verdict is `confirmed`. A script re-derived this from the decision rules; it equals the verifier's `item_assessment`.

The boundary is measured in characters of ASCII text, where one character is one byte. Whether the limit counts bytes or characters for non-ASCII group IDs is not tested.
