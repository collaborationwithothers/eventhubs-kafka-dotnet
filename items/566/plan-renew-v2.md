# Renew version 2 mutation qualifications

A mutation qualification records how long the verifier's mutation tests are expected to take and which source files support that estimate. This change lets an operator record a decision to keep an estimate after a shared input changes. The reviewer checks that the decision covers the changed files and the remaining uncertainty.

Revision 2. One implementation pull request, `renew-v2`. Base on main: `ac14419f5afb6a04251e0137ca38209614482c28`.

## External contracts

Use the same command for both versions: `python3 tests/Parchwell.Verifier.Tests/Mutation/c5_runtime.py renew --head HEAD_SHA --qualification FILE --basis TEXT`. The head resolves to a Git commit. FILE is the operator's qualification file. Keep the existing success JSON and exit 0: `{"renewed":["global.json"],"status":"renewed"}` for that single changed path, or `{"renewed":[],"status":"unchanged"}`. The list contains sorted repository-relative paths changed against the file's previous top-level shared map. Version 2 continues to use `timing_inputs[context].assessments.shared_inputs[path]` with exactly `current_sha256` (lowercase SHA-256 hex or JSON null) and `basis` (a nonempty array of nonblank strings). A timing context is the pair of full input maps recorded for a measurement. Its key is the existing digest of those maps.

`check --head HEAD_SHA --qualification FILE` keeps its existing output, including qualified or provisional status, pending targets if applicable, and the sorted, deduplicated union of all assessments as `assessed_inputs` with `shared_inputs:` or `target_sources:` prefixes. It omits the field for an empty union. No new public schema or flags. Renewal failures return 1, empty standard output, a diagnostic on standard error, and leave the original file intact.

## Requirements and enforced checks

1. WHEN either format is loaded, THEN keep the existing head resolution, loaded runner byte comparison, nonblank basis and schema checks. Retain the full version 1 route, including its refusal of every nonrenewable path, append and reversion semantics, and `renewed_inputs` disclosure by check.
2. WHEN top-level target membership or any current target source hash differs from the requested head, THEN fail with `target sources changed` before publishing. Historic differences already recorded between a timing context and a different target's current hash survive. Renewal never creates a target-source assessment.
3. WHEN processing version 2, THEN derive the changed paths from the union of old and new top-level shared paths. For each changed path in every context, compare the new head to that context's measured map. If equal (including both absent), remove any assessment for the path. If different, write its new hash or null and append the supplied basis to the previous basis array for that path, or start the array with that basis. Retain prior entries in order when updating an outstanding difference. A decision for an earlier hash alone cannot justify a new hash. Preserve unrelated assessments exactly. The new top-level shared map equals the head map. Do not insert a version 1 renewals field.
4. WHEN a top-level nonrenewable shared input changes in version 2, THEN admit only the exact forward transition for the projection helper or runner that the guide names. Compare previous top-level hash to head hash. Reject all other newly changed nonrenewable paths, including reversals, with `not renewable: ` followed by their sorted names, comma-space separated. The candidate must also pass the existing measured-to-head policy for every consuming shard. Preserve and revalidate existing assessments supported by committed-tree equivalence when renewing other paths. New configurations relying on that separately documented proof remain on their existing review path. A basis string cannot establish equivalence.
5. WHEN version 2 renewal would report success, THEN require the candidate to pass the same full-head check as an explicit check without a base. Accept `qualified` and `provisional` with empty reasons. For an invalid candidate, report `qualification rejected: ` followed by its sorted reason codes, comma-space separated, unless an earlier input/refusal check already supplies its diagnostic. Preserve measured maps, context keys and source commits, target records, estimates, indices, evidence and historical entries throughout. Do not manufacture missing assessments on unrelated paths. Use one atomic replacement after validation for an actual change. A repeated call on the same valid head, even with another basis, returns unchanged without rewriting any bytes.
6. WHEN reviewing version 2 output, THEN check that the supplied basis names the authorizing decision and covers the files and uncertainty. The command enforces nonblank text. Review decides whether it establishes authority. The operations guide distinguishes the two responsibilities and retains the main-only mutation acceptance rule.

## Test map

The following inputs are synthetic. In this map A, B and C denote the exact hex digests of the byte strings `b'A'`, `b'B'` and `b'C'` using SHA-256. D1 and D2 denote the exact text `synthetic decision 1` and `synthetic decision 2`. Use named cases or subtests in the existing unittest module.

- Requirements 1, 3, 5, `v2_context_renewal`. Start with two used timing contexts, one measured at A, one at B for `global.json`. Previous current hash A. Only the B context has an assessment, `{current_sha256:A,basis:[D1]}`. At head C with basis D2 expect both to record C, with bases [D2] and [D1,D2] respectively. Expect exactly the single changed path in the command output. At a subsequent head B with basis D1, remove the B context's entry and give the A context `{current_sha256:B,basis:[D2,D1]}`. A second invocation there returns unchanged and identical bytes. Bind each context to its own shard and evidence. Compare the entire result to a copy with only the specified changes, including an existing unrelated target assessment and unrelated shared assessment. The checker reports each assessed path once even when both contexts cite it.
- Requirements 3, 5, `v2_membership`. Start with a measured and current `old.cs` at A and no `new.cs`. Head removes old.cs and adds new.cs at B. Expect renewed paths ["new.cs","old.cs"], assessment for old.cs equal to {current_sha256:null,basis:[D1]}, and new.cs equal to {current_sha256:B,basis:[D1]}. After full reversion expect neither entry, no empty path placeholders, and no assessed_inputs on an otherwise assessment-free fixture.
- Requirements 1, 2, 4, 5, `v2_refusal`. Mix a renewable change with an unapproved tool-manifest change. Expect exit 1 and `not renewable: .config/dotnet-tools.json`. Separately change a target's hash, add one, or remove one. Expect `target sources changed` for each. Supply a whitespace-only basis and expect `basis must not be empty`. Mismatch the loaded runner and expect `checker is not running the requested revision`. Original bytes and directory entries survive every rejection and an injected replacement failure. A missing unrelated assessment must yield `qualification rejected: unaccounted_inputs` on an otherwise valid fixture, including on the unchanged path.
- Requirements 4, 5, `v2_protected_pairs`. Exercise the two exact old-to-new pairs at [the existing constants](../../tests/Parchwell.Verifier.Tests/Mutation/c5_runtime.py#L324) and use the existing positive committed-tree equivalence fixture for a retained approved context. Preserve its recorded assessment when only global.json changes. Check reverse and one-digit-wrong new projection/runner hashes with no valid equivalence proof, and a config edit failing equivalence. Expect exit 1, unchanged file, no success output. The existing checker tests of runner/config equivalence, bound shard ownership and evidence must keep passing. For a newly changed top-level config path, even one independently shown equivalent by the existing checker fixture, expect exit 1 and `not renewable: tests/Parchwell.Verifier.Tests/Mutation/stryker-c5-config.json`.
- Requirements 3, 5, 6, `v2_committed_check`. Exercise the real renew command followed by the real no-base check against one temporary committed shared-file edit. Use a temporary Git commit derived from the pinned base with one synthetic trailing comment added to `src/Parchwell.Verifier/AssemblyInfo.cs` and run from a checkout loading the matching runner. Copy the base's version 2 qualification to a temporary file. Do not mock the checker, timing evidence or input maps. Expect exit 0, renewed list ["src/Parchwell.Verifier/AssemblyInfo.cs"], check status `provisional`, reasons [], pending targets identical to the base, and assessed_inputs equal to the sorted union of the base set and ["shared_inputs:src/Parchwell.Verifier/AssemblyInfo.cs"]. Repeating with another basis leaves bytes identical. Compare each historical record, complete measured map and target record before and after. The pinned base itself returned provisional with empty reasons in the planning read.
- Requirement 1, existing `RenewalTests.test_renew_command` and version 1 checker tests. Keep their exact expectations for success, unchanged, error and no partial write. Requirement 6 also gets document review at the command example, renewal paragraph and migration paragraph.

Existing fixture rule: if a new check rejects an existing fixture, either repair the fixture while retaining every assertion and its boundary, or, for a deliberately invalid input, retain the input and assert exactly the specified invalid result. Never remove a case, loosen an assertion or change a check to accommodate it. List each adjustment and the check that forced it in the implementation notes for cold and Codex review.
