# C5 hosted timing diagnostic

`verifier-c5-sizing.yml` is a manual, CPU-only diagnostic. Dispatch it on `main` only, after the workflow change merges. For the issue 494 duplicate-reporting campaign, leave `source_sha` at `0f41390beadfbec7d0f7d7819bbd834744ca85df`. The workflow rejects other sources and verifies the checked-out commit and each matrix row's target SHA-256.

The matrix contains the 110 affected physical shards from the candidate C5 layout. Each shard has a separate standard `ubuntu-24.04` job. `local-shard` uses the committed selector and required isolation for that physical shard. Its inner deadline is 2,650 seconds, the outer deadline including the termination grace is 2,700 seconds, and the job limit is 50 minutes. Per the [timing decision](https://github.com/collaborationwithothers/eventhubs-kafka-dotnet/issues/494#issuecomment-6976227348), qualification retains the original timing estimates for the 146 unchanged selections. The [source-pin amendment](https://github.com/collaborationwithothers/eventhubs-kafka-dotnet/issues/494#issuecomment-6992683745) also accepts the timing risk of the specified consumer-observation changes. These source and test changes can increase runtime, so the retained estimates may be low. The diagnostic has no aggregate acceptance step.

Each job uploads its diagnostic directory, including raw reports, command logs, configuration, projection, and receipts, even on failure where the runner can perform the upload. Detailed test-server RPC logs upload separately with the same one-day retention. `status.txt` starts as `incomplete`; `completed_unverified` means only that the local-shard command completed its own checks. Inspect the receipt, logs and source and runner metadata before interpreting timings. A missing artifact or receipt is incomplete evidence, not a zero or a pass. These measurements do not qualify a shard or replace the complete, main-only C5 acceptance workflow.

Artifacts expire after one day. Download and preserve the evidence needed for review before expiry. The workflow has read-only contents permission, does not use an environment, secrets or Azure, and does not persist checkout credentials.

On 2026-11-15, [GitHub's billing documentation](https://docs.github.com/en/billing/concepts/product-billing/github-actions) stated that standard hosted runners in public repositories are free. That establishes the compute rule, not an unconditional exemption for artifact storage. This diagnostic does not use a larger runner.
