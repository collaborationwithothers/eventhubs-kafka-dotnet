# G04: one private DNS zone per region

Microsoft says a geo-replicated Event Hubs namespace needs one `privatelink.servicebus.windows.net` private DNS zone per region, linked to that region's virtual network only. This repository does not test it, because the harness runs in a single region and multi-region application deployment is deferred. The main finding is that the documented cost of a shared zone is one A record that points at whichever private endpoint was attached last.

Sources were read on 2026-10-27. Line numbers refer to the linked commit or tag. "Inference" marks a statement that no cited source makes.

## Claim

The [geo-replication page](https://github.com/MicrosoftDocs/azure-docs/blob/6da87e3c59251e962dd0b37dbd99ae364d767150/articles/event-hubs/geo-replication.md) (`ms.date` 07/10/2026) says at line 267: "Use one `privatelink.servicebus.windows.net` private DNS zone per region, linked to that region's virtual network only." The same line adds: "Each region resolves the namespace name to its local endpoint, regardless of which region is primary".

Line 269 gives the cost of sharing: with one shared zone "only one A record exists and it points to whichever endpoint was attached last".

## Why it is traced, not tested

The inventory reason in [docs/blueprint.md](../blueprint.md) section 12 is: "single-region harness". The harness has one region, so there is no second virtual network to link and no second private endpoint to attach.

Multi-region application deployment is also deferred in section 12. Inference: a test would need that deployment first.

## Trace

- Design: ADR-004 allows the namespace through a private endpoint only. ADR-010 keeps the private DNS zones outside this repository's Terraform and states "A VNet can be linked to only one private DNS zone of a given name".
- .NET code: none. Clients connect by namespace name.
- Terraform: the persistent layer names one zone for Event Hubs, `privatelink.servicebus.windows.net` ([locals.tf line 26](https://github.com/collaborationwithothers/eventhubs-kafka-dotnet/blob/39e2cbba73f28855d3d0bbc3511d977294b8ba09/infra/persistent/locals.tf)). It uses a zone this repository created when `create_private_dns_zones` is true, and the platform zone otherwise (line 29). A second region needs a second zone of that name (geo-replication page line 267). Inference from ADR-010: the runner's network can link to only one zone of that name.
- Security: none beyond ADR-004.
- Symptom: line 269 of the geo-replication page. With one shared zone across both virtual networks, only one A record exists, and it points to whichever endpoint was attached last.
- Detection: Inference: resolve the namespace name from each region's network and compare the answer with that region's private endpoint address.
- Runbook: line 269 says to add cross-region virtual network peering when a zone is shared, so all clients can reach that endpoint. Line 259 says "the private endpoint keeps working without any change" after failover.
