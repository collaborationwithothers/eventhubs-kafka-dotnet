# D05: 100 event hubs per PU

Event Hubs Premium documents a limit of 100 event hubs per PU (processing unit, the unit of Premium capacity). This item is traced from documentation because creating event hubs through the Kafka AdminClient is itself in doubt, and the build creates its event hubs with Terraform. The main finding is that, in this harness, only the AdminClient check that D01 may add would create a 101st event hub, and the documented partition limit leaves room for that check.

Sources were read on 2026-10-27. Line numbers refer to the linked commit or tag. "Inference" marks a statement that no cited source makes.

## Claim

The [tier limits page](https://github.com/MicrosoftDocs/azure-docs/blob/6da87e3c59251e962dd0b37dbd99ae364d767150/articles/event-hubs/includes/event-hubs-tier-limits.md) (ms.date 02/05/2026) has the row "Number of event hubs per namespace" at line 31. For Premium it gives "100 per PU".

## Why it is traced, not tested

The inventory reason in [docs/blueprint.md](../blueprint.md) section 12 is "D: documentation trace only".

ADR-002 creates event hubs with Terraform through ARM. The [client configuration page](https://github.com/MicrosoftDocs/azure-docs/blob/6da87e3c59251e962dd0b37dbd99ae364d767150/articles/event-hubs/apache-kafka-configurations.md) lists "Kafka AdminClient for topic management" as not supported at line 150. The [partitions page](https://github.com/MicrosoftDocs/azure-docs/blob/6da87e3c59251e962dd0b37dbd99ae364d767150/articles/event-hubs/dynamically-add-partitions.md) says at line 57 to use `AlterTopics` to add partitions. That is documentation conflict 2 in the blueprint, which D01 tests.

## Arithmetic for the D01 check

The namespace holds three event hubs of 32, 4 and 32 partitions ([infra/ephemeral/eventhubs.tf](https://github.com/collaborationwithothers/eventhubs-kafka-dotnet/blob/39e2cbba73f28855d3d0bbc3511d977294b8ba09/infra/ephemeral/eventhubs.tf) lines 9, 15, 16 and 53 to 56). Ninety-seven creates reach 100 event hubs, so the 98th create is the 101st event hub. The partitions then total 68 + 98 = 166, under the "200 per PU at the namespace level" on the tier limits page, line 29 (computed by script).

[Decision 2 on #224](https://github.com/collaborationwithothers/eventhubs-kafka-dotnet/issues/224#issuecomment-6438353573) sets the rule. D01 adds the check only if `CreateTopics` creates event hubs. It then creates one-partition topics until the client returns an error and records that error. Otherwise this trace stands alone.

## Trace

- Design: ADR-002 gives applications no topic-creation rights.
- .NET code: none. Application code does not create event hubs.
- Terraform: the `event_hubs` map and the `document-state` resource in eventhubs.tf.
- Security: the D01 check needs whatever topic-creation right D01's plan grants.
- Symptom: the tier limits page states no error for the 101st event hub, so the symptom is unknown.
- Detection: Inference: compare the event hub count with 100 times the PU count.
- Runbook: assign more PUs (tier limits page, line 31).
