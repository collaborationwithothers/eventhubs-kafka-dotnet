# H03: UnknownServerException

Microsoft warns that clients of Event Hubs for Apache Kafka "might receive an UnknownServerException" and says to open a support ticket. This repository does not test it, because the error cannot be triggered deliberately. The main finding is that the error arrives in Confluent.Kafka as error code -1, which `Error.IsLocalError` and `Error.IsBrokerError` both report as false.

Sources were read on 2026-10-27. Line numbers refer to the linked commit or tag. "Inference" marks a statement that no cited source makes.

## Claim

The [Apache Kafka troubleshooting guide for Event Hubs](https://github.com/MicrosoftDocs/azure-docs/blob/6da87e3c59251e962dd0b37dbd99ae364d767150/articles/event-hubs/apache-kafka-troubleshooting-guide.md) (`ms.date` 03/06/2025) has a section "UnknownServerException" at lines 31 to 38. It says clients "might receive an UnknownServerException" and gives the Java text "The server experienced an unexpected error when processing the request". Its guidance is: "Open a ticket with Microsoft support. Debug-level logging and exception timestamps in UTC are helpful in debugging the issue."

## Why it is traced, not tested

The reason in [docs/blueprint.md](../blueprint.md) section 12 is: "cannot be triggered deliberately".

The page names no request, input or condition that causes the error. Inference: without a known cause, a scenario cannot raise it on purpose, and a run that did not see it would show nothing.

## The error code in Confluent.Kafka

The code travels from the Kafka protocol to the .NET type through four sources.

- Apache Kafka 4.1.0, [Errors.java](https://github.com/apache/kafka/blob/4.1.0/clients/src/main/java/org/apache/kafka/common/protocol/Errors.java), lines 179 and 180, maps `UnknownServerException` to code -1, named `UNKNOWN_SERVER_ERROR`.
- librdkafka v2.16.0, [src/rdkafka.h](https://github.com/confluentinc/librdkafka/blob/v2.16.0/src/rdkafka.h), lines 423 and 424, names code -1 `RD_KAFKA_RESP_ERR_UNKNOWN`, with the comment "Unknown broker error".
- Confluent.Kafka v2.16.0, [ErrorCode.cs](https://github.com/confluentinc/confluent-kafka-dotnet/blob/v2.16.0/src/Confluent.Kafka/ErrorCode.cs), lines 349 to 352, names code -1 `ErrorCode.Unknown`, with the same comment.
- Inference: a reply that carries code -1 reaches .NET as `ErrorCode.Unknown`. No cited source states the mapping end to end for this error.

The two origin flags sit in [Error.cs](https://github.com/confluentinc/confluent-kafka-dotnet/blob/v2.16.0/src/Confluent.Kafka/Error.cs), lines 203 to 210. `IsLocalError` is true only when the code is below -1. `IsBrokerError` is true only when the code is above 0. For -1, both are false.

## Trace

- Design: none.
- .NET code: a classifier that checks both `IsLocalError` and `IsBrokerError` puts code -1 in neither class. This repository checks one flag and falls back to the other class, in two opposite ways. [SingleActionCapture.cs](https://github.com/collaborationwithothers/eventhubs-kafka-dotnet/blob/39e2cbba73f28855d3d0bbc3511d977294b8ba09/src/Parchwell.LoadGen/SingleAction/SingleActionCapture.cs) line 109 labels any error that is not `IsBrokerError` as "local". [SeedF04Worker.cs](https://github.com/collaborationwithothers/eventhubs-kafka-dotnet/blob/39e2cbba73f28855d3d0bbc3511d977294b8ba09/src/Parchwell.Enrichment/SeedF04/SeedF04Worker.cs) line 71 labels any error that is not `IsLocalError` as "broker". Inference: code -1 would be labelled "local" by the first and "broker" by the second.
- Terraform: none. The error has no setting.
- Security: none.
- Symptom: error code -1. Inference: it can come back on any request type, because the page ties it to no request.
- Detection: log the error code with a UTC timestamp, as the page asks for exception timestamps in UTC.
- Runbook: follow the page (line 38): open a ticket with Microsoft support and attach debug-level logging with UTC timestamps. librdkafka v2.16.0 [CONFIGURATION.md](https://github.com/confluentinc/librdkafka/blob/v2.16.0/CONFIGURATION.md), line 24, says `debug` takes a comma-separated list of contexts to enable.
