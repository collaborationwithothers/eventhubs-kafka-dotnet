# K10: SNAT port use for Entra egress

SNAT (source network address translation) is how the AKS load balancer lets nodes open connections to public addresses, and each outbound connection holds a SNAT port until it is released. This item is not tested because exhaustion needs scale. The main finding is that the build cluster has one node per pool, inside the range of 50 or fewer nodes where the default gives each node 1024 ports, and that the token requests to Entra are, by inference, the SNAT consumer to watch.

Sources were read on 2026-10-27. Line numbers refer to the linked commit or tag. "Inference" marks a statement that no cited source makes.

## Claim

The AKS page [configure-load-balancer-standard.md](https://github.com/MicrosoftDocs/azure-aks-docs/blob/1b2c1f91df475f8cb46f72cbf3ee125241523be8/articles/aks/configure-load-balancer-standard.md) (`ms.date` 09/08/2026) line 201 says: "By default, AKS sets _AllocatedOutboundPorts_ on its load balancer to `0`". It continues: "For example, if a cluster has 50 or fewer nodes, 1024 ports are allocated to each node."

Line 289 says what happens at the limit: "When SNAT port resources run out, outbound flows stop working until existing flows release SNAT ports". The same line says that "the AKS-configured load balancer uses a 30-minute idle timeout for reclaiming SNAT ports from idle connections".

## Why it is traced, not tested

The reason in section 12 of the inventory in [docs/blueprint.md](../blueprint.md) is: "exhaustion needs scale".

The cluster's outbound path is the load balancer: `outbound_type = "loadBalancer"` (line 31 of [aks.tf](https://github.com/collaborationwithothers/eventhubs-kafka-dotnet/blob/39e2cbba73f28855d3d0bbc3511d977294b8ba09/infra/cluster/aks.tf)). Each of the three pools has one node (aks.tf lines 35, 44 and 51).

Inference: at that size each node holds its full default share of ports, and token refresh opens few connections, so exhaustion would need far more clients or nodes than a build-scale run has.

## Unconfirmed

Whether private endpoint traffic uses SNAT ports is unconfirmed. The [catalogue](../research/kubernetes-kafka-clients.md) entry K-41 lists the limits as confirmed and the bypass as unconfirmed, and the catalogue's open questions repeat it. No cited source states it. This write-up therefore makes no claim about the Kafka data path, only about the public Entra path.

## Trace

- Design: ADR-003 has clients acquire Entra tokens with workload identity, and ADR-004 puts the Event Hubs data path on a private endpoint. Inference: the Entra token endpoint is public, so token requests use SNAT ports.
- .NET code: the ADR-003 OAUTHBEARER refresh handler is attached to each producer and consumer builder in `KafkaAuthenticationFactory.cs` (lines 81 and 104 of [the file](https://github.com/collaborationwithothers/eventhubs-kafka-dotnet/blob/39e2cbba73f28855d3d0bbc3511d977294b8ba09/src/Parchwell.Kafka/Authentication/KafkaAuthenticationFactory.cs)).
- Terraform: no explicit allocated ports are set; aks.tf line 31 sets only the outbound type, so the default of `0` applies (configure-load-balancer-standard.md line 201).
- Security: none beyond ADR-003 and ADR-004. No secret is involved, and the path is outbound only.
- Symptom: outbound flows stop working until existing flows release SNAT ports (configure-load-balancer-standard.md line 289). Inference: token refresh fails, then the client cannot authenticate to Event Hubs.
- Detection: the AKS page [troubleshoot-source-network-address-translation.md](https://github.com/MicrosoftDocs/azure-aks-docs/blob/1b2c1f91df475f8cb46f72cbf3ee125241523be8/articles/aks/troubleshoot-source-network-address-translation.md) line 27 says to check Azure Monitor metrics and logs, for example the "Failed" category of the SNAT connections metric.
- Runbook: configure-load-balancer-standard.md line 201 says "We recommend using an explicit value for _AllocatedOutboundPorts_." The troubleshooting page line 33 says to "Take advantage of connection reuse and connection pooling whenever possible."
