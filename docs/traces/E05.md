# E05: 250 GB per partition on compacted event hubs

Event Hubs Premium documents a compacted event hub size of 250 GB per partition. This item is traced from documentation because, in the inventory's words, it is beyond build scale. The main finding is an open question: no cited source says whether compacted storage counts against the retention storage of 1 TB per PU (processing unit, the unit of Premium capacity).

Sources were read on 2026-10-27. Line numbers refer to the linked commit or tag. "Inference" marks a statement that no cited source makes.

## Claim

The [tier limits page](https://github.com/MicrosoftDocs/azure-docs/blob/6da87e3c59251e962dd0b37dbd99ae364d767150/articles/event-hubs/includes/event-hubs-tier-limits.md) (ms.date 02/05/2026) has the row "Size of compacted event hub" at line 33. For Premium it gives "250 GB per partition".

## Why it is traced, not tested

The inventory reason in [docs/blueprint.md](../blueprint.md) section 12 is "D: beyond build scale".

Inference: the synthetic workload of the build cannot fill a compacted partition to 250 GB. The open question below shows that the documented limits also leave the capacity unsettled.

## Open question: compacted storage and the 1 TB per PU

The compacted event hub `document-state` has 32 partitions ([infra/ephemeral/eventhubs.tf](https://github.com/collaborationwithothers/eventhubs-kafka-dotnet/blob/39e2cbba73f28855d3d0bbc3511d977294b8ba09/infra/ephemeral/eventhubs.tf) line 56). Then 32 x 250 GB = 8,000 GB (computed by script). The tier limits page gives "1 TB per PU" for event storage for retention at line 27. No cited source says whether compacted storage counts against it. Inference: if it does, a namespace with 1 PU cannot hold 250 GB in every partition at once. This is recorded as undocumented.

## Trace

- Design: ADR-002 fixes the partition count of compacted event hubs.
- .NET code: none. Application code does not set or read the size limit.
- Terraform: the `Compact` cleanup policy with 168 hours of tombstone retention (eventhubs.tf lines 53 to 60).
- Security: none. The item changes no identity, network or credential setting.
- Symptom: the tier limits page states none, so the symptom is unknown.
- Detection: no cited source names a per-partition size signal.
- Runbook: none stated in the cited sources.
