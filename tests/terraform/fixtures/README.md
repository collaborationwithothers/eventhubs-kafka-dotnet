# Terraform mock fixtures

These native Terraform tests use synthetic identifiers, addresses, hostnames, timestamps and version strings. They keep the actual pinned Azure Verified Modules and replace computed provider responses in plan mode. No Azure identity or backend connectivity is used. Root-local `tests` symlinks expose these canonical files through Terraform's required local testing-directory argument.

The [Terraform roots plan](https://github.com/collaborationwithothers/eventhubs-kafka-dotnet/issues/157#issuecomment-6385941149), with its [later ownership decision](https://github.com/collaborationwithothers/eventhubs-kafka-dotnet/issues/157#issuecomment-6386075427), moves the existing checks to their owning roots and adds monitoring coverage. The test files are [persistent](../persistent/main.tftest.hcl), [cluster](../cluster/main.tftest.hcl) and [ephemeral](../ephemeral/main.tftest.hcl). Run them with the [offline commands](../../../docs/operations/terraform.md#offline-checks).

Mocks supply resource IDs, identity client/principal IDs, private IPs and ARM response objects. Configured access flags, resource bodies, role scopes, tags, retention and pool definitions remain those of the actual modules. Where a module exposes only response fields, tests pair its supported outputs with the exact named configuration local passed into the module; this is input/output contract coverage rather than inspection of hidden provider resources.

The cluster fixture supplies the AKS OIDC issuer and kubelet-identity response shape and a synthetic user kubeconfig containing a cluster certificate field. It is not a usable kubeconfig. The Container Insights data collection rule receives only a synthetic computed ID and output; its configured extension, destination and data-flow assertions inspect the real module's ARM body. Application Insights computed fields now belong to the persistent fixture, including its synthetic connection string. The storage endpoint read returns a synthetic private-service connection; its approved status is fixture data, not observed endpoint readiness. Remote persistent state supplies the outputs consumed by the dependent roots; the test backend name is never contacted.

Persistent positive cases cover existing external DNS zones, optional standalone zone ownership and Application Insights. Cluster coverage retains the AKS security, fixed pools and federation checks and adds the subnet role, Entra-enabled monitoring and Container Insights association. Ephemeral positive coverage retains the fixed A01 Event Hubs, storage, diagnostics and scoped data-role contract. Both dependent roots test the explicit OIDC and non-OIDC remote-state configurations. Negative cases change the exact variable named by each test and expect its validation failure; an unrelated provider or expression error does not count as successful rejection.

The tag map and existing external backend follow [Hari's decision](https://github.com/collaborationwithothers/eventhubs-kafka-dotnet/issues/112#issuecomment-6318488448). No root provisions or migrates the existing state account. Mocks establish neither identity permissions nor live telemetry ingestion. Live backend access, network overlap, Kubernetes GA availability, CLI login, deployed table retention, cluster restart and service behavior remain later deployment/run evidence.

Probe coverage adds the probe identity and federation, its component-scoped telemetry grant, and the single-action container's exact scoped role set. These remain synthetic configuration checks; the image smoke does not exercise data-plane permissions.
